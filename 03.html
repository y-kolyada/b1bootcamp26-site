    Занятие 3 · Возврат: работа не принята

    К концу занятия у тебя есть первая настоящая функция продукта и хотя бы один честный возврат. Ты учишься читать git diff, возвращать работу по предикатам и откатывать неудачные шаги за одну секунду - не переделывая руками.

    Главная мысль занятия #

    Слова ИИ - не доказательство. Доказательство - команда git diff. В конце каждого ответа ИИ уверяет, что он всё сделал безупречно. Верить этому на слово нельзя. Доказательство - это зелёные строки добавленного и красные строки удалённого в реальных файлах твоего репозитория. Вторая мысль занятия - коммит до того, как просишь. Сохранение стоит десять секунд, но даёт тебе несгораемую точку возврата: если машина ошиблась, одна команда git restore мгновенно возвращает всё на место. И главное правило взрослого инженера: никогда не переделывай за ИИ руками. Если предикат нарушен - возвращай работу машине с указанием точной причины.

    1 · Цель занятия #

    Научиться управлять качеством и говорить машине «нет». ИИ часто делает что-то похожее, но пропускает важные детали или ломает то, что работало до него. Наша цель сегодня:

    • создать первую интерактивную функцию своего продукта (кнопку с действием, переключатель, форму или список);
    • поставить точку возврата - сделать КоммитНесгораемая точка сохранения в истории проекта с понятным описанием.Где встретилось: Занятие 1 → В словарь понятий в Git до того, как отдавать команду;
    • освоить ДиффКоманда терминала, показывающая реальную разницу между файлами до и после работы.Где встретилось: Занятие 1 → В словарь понятий - отличать зелёные добавления + от красных удалений -;
    • сделать честный возврат - найти невыполненный предикат, отклонить работу и заставить ИИ исправить ошибку.

    Как читать дифф: факты против слов #

    Когда программист смотрит на результат, он не читает объяснения модели. Он запускает git diff:

    • Зелёные строки с плюсом (+) - то, что реально добавлено в файл. Проверь: это ровно то, о чём просил предикат? Нет ли там лишнего мусора?
    • Красные строки с минусом (-) - то, что удалено. Самая частая скрытая поломка: ИИ «забыл» половину твоих прежних стилей или заголовок.

    Если в диффе есть красные строки, которые ты удалять не просил, или нет того, что требует предикат - работа не принята.

    2 · Путь-минимум: мышкой, без терминала #

    Этого пути достаточно, чтобы сделать первую функцию продукта и провести возврат прямо в редакторе.

    1 Третья пара артефактов #

    В проводнике файлов редактора создаём третью пару артефактов:

    1. Скопируй zadanie-2.md и назови копию zadanie-3.md.
    2. Скопируй zapis-2.md и назови копию zapis-3.md.

    Или одной строкой в терминале (микро-цель: подготовить чистые бланки для третьего занятия):

    cp zadanie-2.md zadanie-3.md
cp zapis-2.md zapis-3.md
    Должно напечатать: ничего (тишина означает, что файлы скопированы успешно).
    После шага существует: файлы zadanie-3.md и zapis-3.md в корне твоего проекта.
    2 Задание на первую функцию и коммит сохранения #

    Открой zadanie-3.md и сформулируй задачу на интерактивную функцию для твоей страницы. Например:

    • Хочу: интерактивную кнопку счётчика кликов на странице.
    • Предикат 1: на странице есть кнопка с текстом «Нажми меня» и идентификатором counter-btn.
    • Предикат 2: рядом отображается текст «Нажатий: 0».
    • Предикат 3: при каждом клике на кнопку число увеличивается на единицу, без перезагрузки страницы.

    Зафиксируй сохранение ДО запуска ИИ.

    В редакторе: вкладка Source Control → сообщение docs: задание 3 и точка возврата → Commit.

    Или в терминале (микро-цель: ставим несгораемую точку в Git, к которой сможем вернуться при любой ошибке):

    git add zadanie-3.md zapis-3.md
git commit -m "docs: задание 3 и точка возврата"
    Должно напечатать: строку коммита с подтверждением сохранения.
    После шага существует: коммит сохранения, защищающий проект от поломок.
    3 Попроси ИИ и посмотри дифф в Source Control #

    Открой чат с ИИ и отправь задачу строго по заданию:

    Сделай задачу из zadanie-3.md. Напиши код в index.html. Не меняй ничего лишнего.

    Когда ИИ закончит и напишет, что всё готово, не верь ему на слово. Перейди во вкладку Source Control (слева) и нажми на файл index.html.

    Редактор откроет окно сравнения: слева старый файл, справа новый. Проверь глазами:

    • появилась ли кнопка с нужным id?
    • есть ли начальный текст «Нажатий: 0»?
    • не стёр ли ИИ твои стили или прошлый текст (нет ли лишних красных строк)?
    После шага существует: изменённый файл index.html, проверенный твоими глазами в окне сравнения.
    4 Честный возврат: найди ошибку и верни работу #

    Открой страницу в браузере и нажми на кнопку. Если она не работает, или текст отличается от предиката, или ИИ забыл начальный ноль - это возврат.

    (Даже если ИИ угадал всё с первого раза, найди мелкую неточность - например, шрифт, отступ или текст - и потребуй исправить именно её, чтобы отработать возврат.)

    Ничего не исправляй руками! Напиши ИИ в чат:

    Работа не принята. Предикат 2 нарушен: счётчик не обновляет цифру на экране при клике.
Исправь JavaScript в index.html, соблюдая все три предиката из zadanie-3.md.

    ИИ прочитает замечание и перепишет код. Снова открой вкладку Source Control и проверь изменения.

    После шага существует: исправленный код, доведённый до соответствия предикатам без единой ручной правки.
    5 Заполни zapis-3.md и отправь на GitHub #

    Открой zapis-3.md и честно запиши ход приёмки:

    • какой предикат был нарушен в первой попытке;
    • что ты ответил ИИ для возврата;
    • итог проверки: «Принято после исправления».

    Запечатай работу в Git и отправь на GitHub:

    git add index.html zapis-3.md
git commit -m "feat: первая функция и честный возврат по заданию 3"
git push
    Должно напечатать: строку отправки ветки в удалённый репозиторий GitHub.
    После шага существует: опубликованный сайт с интерактивной функцией и зафиксированная история возврата.

    3 · Путь-100%: в терминале через Claude Code #

    Путь настоящего инженера: проверка диффа прямо в консоли и мгновенный откат неудачных правок.

    1 Чтение git diff в терминале #

    После того как Claude Code изменил файлы, выполни в терминале команду проверки (микро-цель: увидеть реальные факты изменений без запуска графического редактора):

    git diff index.html
    Должно напечатать: блок изменений, где зелёные строки начинаются с +, а удалённые - с -.

    Строка @@ -15,4 +15,12 @@ показывает номера изменённых строк. Внимательно посмотри на знаки минус: если ИИ снёс нужную часть страницы, ты увидишь это сразу.

    После шага существует: ясная картина изменений в терминале.
    2 Опасная сила отката: git status перед git restore #

    Если ИИ запутался и нагородил ерунды, не пытайся судорожно нажимать Ctrl+Z. Твой коммит сохранения из шага 2 помнит чистое состояние. Но перед тем как стирать, всегда посмотри, что именно исчезнет (микро-цель: увидеть список несохранённых файлов своими глазами):

    git status
    Должно напечатать: список файлов красным цветом под строкой Changes not staged for commit (например: modified: index.html).

    Предупреждение, которое спасёт твою работу. Команда git restore . безжалостна: точка . означает «откатить абсолютно всё в текущей папке». Она сметёт все несохранённые изменения - не только то, что нагенерировал ИИ, но и твои собственные правки, если ты забыл их закоммитить! Поэтому правило железное: сначала проверь глазами через git status, и только потом делай откат.

    Теперь откатываем неудачный эксперимент к чистому сохранению:

    git restore .
    Должно напечатать: ничего (в Linux тишина означает, что файлы мгновенно вернулись к последнему коммиту).

    Запусти git status снова - терминал напишет nothing to commit, working tree clean. Проект спасён!

    После шага существует: чистое исходное состояние проекта с пониманием того, что и почему было отменено.
    3 Прицельный возврат в Claude Code #

    Запусти Claude Code с указанием точной причины возврата:

    claude "Сделай задачу из zadanie-3.md. В прошлый раз не работал предикат 3. Сделай строго по предикатам, не трогая разметку шапки и подвала."
    Должно напечатать: отчёт Claude Code о точечном изменении кода по заданным условиям.
    После шага существует: исправленный index.html, созданный с учётом твоих требований.
    4 Проверка статистики диффа и публикация #

    Перед коммитом посмотри компактную сводку изменений (микро-цель: убедиться, что затронуты только нужные файлы и число строк адекватно):

    git diff --stat
    Должно напечатать: список файлов и количество добавленных/удалённых строк (например, index.html | 14 +++-).

    Если всё сходится - сохраняй и публикуй:

    git add index.html zapis-3.md
git commit -m "feat(core): первая интерактивная функция и успешный возврат"
git push
    Должно напечатать: строки отправки изменений на GitHub.
    После шага существует: отправленный в сеть коммит с чистым диффом.

    4 · Путь-максимум: продолжение следует #

    Для тех, кто хочет сделать свою среду разработки ещё надёжнее.

    1 Защита от тихого удаления кода в AGENTS.md #

    ИИ очень любит переписывать файлы целиком, выбрасывая «неважные», по его мнению, куски. Добавь в свой файл AGENTS.md четвёртое строгое правило:

    5. Правило сохранения: никогда не удаляй существующие функции, классы и стили, если об этом прямо не сказано в предикатах задания. При сомнениях - только добавляй новое.

    Зафиксируй улучшение правил в Git (микро-цель: обучить ИИ бережному отношению к существующему коду):

    git add AGENTS.md
git commit -m "chore(rules): правило защиты существующего кода от удаления"
    Должно напечатать: подтверждение сохранения файла правил.
    После шага существует: усиленный файл AGENTS.md с защитой от непреднамеренных удалений.

    5 · Артефакты: что у тебя есть после занятия #

    Занятие >> Твой квант времени жизни · Партнёрство достоинства вместе с AI · Перестройка твоей нейросети

    Занятие - это занятая тобой часть времени твоей жизни. Ты инвестировал своё внимание не в просмотр чужих роликов, а в создание собственного работающего инструмента. Главный артефакт сегодняшнего дня - не просто строчки в репозитории, а твоя новая привычка: не верить словам на экране, проверять факты по диффу и уверенно возвращать некачественную работу. Твоя нейросеть научилась быть требовательным архитектором.

    Материальный перечень артефактов третьего занятия:

    1. zadanie-3.md - цель и три проверяемых предиката для первой настоящей функции твоего продукта. В коммите.
    2. Несгораемая точка возврата - коммит сохранения в Git, сделанный до генерации кода.
    3. index.html - обновлённая страница с работающей функцией, проверенная через git diff. В коммите.
    4. zapis-3.md - честная запись проверки с зафиксированным возвратом и исправлением. В коммите.
    5. Умение читать git diff и использовать git restore - практический навык управления кодовой базой.

    Памятка: команды возврата и проверки Git

    Команды, которые делают тебя хозяином ситуации:

    • git diff - показать реальные изменения: зелёные добавления + и красные удаления -.
    • git diff --stat - краткая сводка: какие файлы затронуты и сколько строк изменилось.
    • git restore <файл> - стереть неудачные правки в одном файле и вернуть его к последнему коммиту.
    • git restore . - мгновенно отменить ВСЕ незакоммиченные изменения во всём проекте.

    Не успеть - это нормально #

    Занятие рассчитано так, что успеть можно. Но если не успеваешь - продолжай с того номера, на котором пришлось остановиться: номера на этой странице и в занятии одни и те же, и страница никуда не денется.

    Сначала спроси своего ИИ, потом тренера. Покажи ИИ команду или дифф, который вызвал затруднение, и спроси, что пошло не так. Если не помогло - пиши в Telegram, в чат «aibootcamp26 chat», одну строку в таком виде:

    шаг 3 · последняя строка: error: pathspec 'index.html' did not match any file(s)
спросил ИИ - предложил проверить git status, не помогло

    Номер шага, последняя строка терминала и что ответил ИИ. Этого хватает, чтобы тренер ответил сразу.
